# ParetoMarker

ParetoMarker is a computational workflow for network-informed candidate biomarker selection and multi-objective optimization.

**Expression preprocessing → PCA-CMI network refinement → differential mutual-information weighting → source-centered information-flow modules → module-seeded multi-objective optimization → recurrence-based gene voting.**

## Repository contents

| Stage | Language | Entry point |
|---|---|---|
| Missing-value filtering, KNN imputation, and optional limma target selection | R | `R/preprocess.R` |
| PCA-CMI network refinement and between-state mutual-information edge weighting | R | `R/preprocess.R`, `R/PCA_CMI.R` |
| Bounded source-target paths, information-flow selection, candidate export, and initial-module masks | Python | `python/flow.py` |
| Module-seeded five-objective search, MLP-guided candidate updates, alpha/beta dynamic selection, and gene voting | MATLAB | `matlab/run_paretomarker.m` |

This repository contains the core ParetoMarker algorithm. Downstream validation analyses, manuscript figures, and manuscript tables are not part of the core algorithm release. The classifier used to calculate the AUC optimization objective is included in the MATLAB search implementation.

## Installation

Python dependencies:

```bash
python -m pip install -r requirements.txt
```

R packages: `impute`, `limma`, and `infotheo`.

MATLAB requires Statistics and Machine Learning Toolbox. Additional MATLAB source dependencies included with this repository are described in `THIRD_PARTY_NOTICES.md`.

## Input data

The workflow requires:

- a numeric gene-expression matrix;
- sample metadata with binary phenotype labels;
- a directed regulatory network;
- source and target gene sets.

Detailed file formats and stage interfaces are described in [`docs/INPUTS.md`](docs/INPUTS.md).

## Running the workflow

Run the R and Python stages from the repository root:

```bash
Rscript R/preprocess.R config/preprocess.example.R
python python/flow.py --config config/flow.example.json
```

Then run the MATLAB stage from the repository root:

```matlab
addpath('matlab');
run_paretomarker('config/optimization.example.json');
```

Use a new output directory for each run.

`config/optimization.example.json` specifies the manuscript search setting: population size 8, 800 candidate-solution evaluations, alpha = 0.4, beta = 3, and a voting fraction of 0.5. With eight initial modules, 800 evaluations correspond to the initial population followed by 99 evolutionary updates. The voting rule retains genes occurring in at least four of the eight final candidate solutions.

`config/optimization.quick.json` uses 16 evaluations and is provided only for a short interface check.

A synthetic input is provided for checking the Python stage:

```bash
python python/flow.py --config config/flow.synthetic.json
```

## Stage outputs

The R stage produces an aligned expression matrix, phenotype labels, source and target genes, and a weighted candidate network. The Python stage identifies source-centered information-flow modules and exports the MATLAB input files, including `initial_population.csv`. Each row of this file is a binary mask for one source-centered module.

The MATLAB stage uses these module masks directly as the initial evolutionary population. For the manuscript configuration, exactly eight non-empty modules are required; the program raises an error if the module count is inconsistent with the configured population size. The search evaluates five objectives in the following order:

1. ROC AUC;
2. negative AIC-like complexity criterion;
3. phenotype association score (PAS);
4. expression entropy;
5. network modularity.

Candidate updates are generated by the MLP-guided evolutionary procedure, followed by alpha/beta dynamic selection. The final output includes gene vote counts, selected genes, and the final candidate population.

## Reproducibility notes

The repository provides explicit file interfaces between the R, Python, and MATLAB stages. Synthetic data are included only to demonstrate file formats and program interfaces. Manuscript performance estimates require the study datasets described in the article and are not reproduced by the synthetic example.

Further implementation details are provided in [`docs/IMPLEMENTATION.md`](docs/IMPLEMENTATION.md), and software requirements are listed in [`docs/DEPENDENCIES.md`](docs/DEPENDENCIES.md).
